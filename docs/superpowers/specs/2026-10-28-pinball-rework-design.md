# 핀볼 개편 · 마블룰렛 수준의 속도감과 한 화면 레이아웃

날짜: 2026-10-28
참고: lazygyu/roulette (MIT) — `camera.ts`, `roulette.ts`, `minimap.ts`, `rankRenderer.ts`, `data/maps.ts`의 Wheel of fortune 구조.

## 목표
핀볼 추첨이 마블룰렛처럼 "떨어지는 속도가 보이고, 결승 직전에만 숨을 죽이는" 흐름이 되게 한다. 코스는 우리 것(스타크래프트 테마 5개)을 유지하되 장애물을 대폭 덜어내고, 설정은 코스 화면 위에 떠 있는 패널로 옮겨 한 화면에 모두 보이게 한다.

## 범위
- 포함: 코스 5개 재설계, 카메라·속도 규칙 교체, 캔버스 전체 화면 레이아웃과 HUD(미니맵·순위·이름표), 떠 있는 설정 패널, 테스트 보강.
- 제외: 세션 저장 포맷(`DrawRun`) 변경, 맵 추첨·ACE 모드의 규칙 변경, 효과음, 송출 창(`OUTPUT`)의 별도 레이아웃(같은 `DrawStage`를 쓰므로 함께 바뀐다).

## 1. 코스 재설계 (`src/courses.ts`)

### 원칙
- 길이: `goalY` 110~120. 스폰은 지금처럼 y 0~3, x 9.75~16.
- 폭: 스폰 레인 7유닛(x 9~17)에서 시작해 넓은 구간은 x 1~25까지 연다.
- 60% 이상이 벽만 있는 낙하·지그재그 구간. 장애물 막대는 두께 0.1, 반발 0~0.3.
- 범퍼는 `kick` 0(차올리기 없음). 빛나는 연출만 남긴다. 진동 플리퍼(`motion`)는 쓰지 않는다.
- 코스당 엔티티 50개 이하(벽 폴리라인 포함).
- 구성 순서: 스폰 → 지그재그 낙하 → 테마 구간 → 넓은 낙하 → 핀 격자(파친코, 0.25 마름모 3줄) → 깔때기(폭 1.0 통로) + 회전 게이트 → 결승.
- 깔때기 구역을 `zoomZone`(x 13, 폭 8, 높이 10, 중심 goal-4)으로 지정한다. 카메라 줌인과 슬로모션은 이 구역에서만 걸린다.

### 코스별 테마 구간
| 코스 | goalY | 테마 구간 |
|---|---|---|
| 시즈 브레이커 | 116 | y 60 근처 회전 막대 5개 한 줄(폭 2, 각속도 ±3.5, 교대) + 그 위 갈매기형 분산판 2줄(0.6×0.1, ±45°) |
| 뮤탈리스크 런 | 118 | 좌·우 곡선 레인 2개(기존 `curvedLane`에서 범퍼 제거) + 터지는 구슬(life 1) 7개 군집 |
| 아이어의 관문 | 114 | 마름모 크리스탈 섬 2개(한 변 1.8, 벽으로 길 가르기) + 파일런 핀 격자 |
| 차 행성 강하 | 120 | 가장 긴 자유 낙하(30유닛) + 마그마 터지는 구슬 2줄 + 큰 회전 막대 1개(폭 5.6, 각속도 -1.25) |
| 나이더스 커널 | 112 | 좁은 지그재그 터널(기존 셸 유지), 끝의 밀집 구간은 핀 격자 + 회전 막대 1개로 축소 |

`sectorLabels`는 3개씩 유지하고 y만 새 구간에 맞춘다. `DEFAULT_COURSE`(나이더스 커널)와 인덱스 순서는 유지한다.

### 물리 (`src/pinball.ts`)
- `kick` 처리 코드는 남기되 코스에서 0을 쓴다(저장된 추첨 재생 호환).
- `ProgressMap.for(stage)`는 그대로. 코스 폭이 넓어져도 `distanceAt`은 벽 기준으로 계산되므로 변경 없음.
- 정지 감시(`stuck`)는 유지.

## 2. 카메라·속도 (`src/PinballStage.tsx`)

### 카메라 (참고 `camera.ts` 이식, 월드 단위)
- 기본 배율: 캔버스 폭 1600px 기준 60px/유닛(`INITIAL_ZOOM`), 줌 1에서 가로 약 27유닛. 마블룰렛은 화면 절반 해상도의 씬 캔버스에 30px/유닛으로 그려 2배로 띄우므로 실제 보이는 폭이 이와 같다. 캔버스는 1600×900 논리 크기, 1배 해상도로 그린다.
- 렌더링은 마지막 두 물리 스텝 사이를 보간해 그린다(슬로모션에서 10ms 스텝이 여러 프레임에 한 번만 돌아도 움직임이 끊기지 않게). 물리 자체는 고정 10ms 스텝이라 창마다 결과가 같다.
- 발광은 shadowBlur 대신 넓은 반투명 선 + 가는 밝은 선 두 번 그리기로 낸다(성능).
- 추적 대상: 첫 골인 전에는 선두. 이후에는 커트라인 구슬(`rank - 도착 수` 번째)과 바로 뒤(없으면 앞) 경쟁자.
- 둘을 한 화면에 담을 배율이 0.6 이상이면 둘을 담고, 0.35 아래면 대상만 따라간다. 그 사이는 보간.
- 줌 강도 `intensity`(0~1)는 `zoomZone`에서만 생기며 최대 4배까지 줌인한다.
- 대상 교체는 20프레임 동안 순위가 유지돼야 하고, 바뀔 때 36프레임에 걸쳐 전환. 보간은 매 프레임 1/10.
- 준비 화면(추첨 전)은 스폰 구역을 1.5~3배로 담는다.

### 속도
- 물리 틱 10ms, 1× 기준 실시간. 1×/2×/4× 버튼은 유지.
- 슬로모션: 커트라인 구슬(또는 더 강한 경쟁자)의 `intensity`가 0보다 크고 경쟁자가 있을 때 `max(0.2, 1 - intensity)`. 그 외에는 항상 1.
- 8배(첫 골인 뒤), 5배(마지막 한 개) 자동 가속 규칙 삭제.
- 순위 흔들림 완화: 남은 거리를 0.4초 EMA로 따라가고 0.25유닛 이상 앞서야 자리를 바꾼다(참고 `_sortMarbles`).

## 3. 화면 (`src/PinballStage.tsx`, `src/pinball.css`)
- 캔버스 논리 1600×900, 스테이지가 콘텐츠 영역을 가득 채우고 `object-fit: contain`.
- 배경 검정(#0b0f10). 벽 흰색 발광(shadowBlur 15), 막대 하늘색, 범퍼·터지는 구슬 노란색/코스 액센트, 회전체는 액센트 색.
- 구슬: 반지름 0.25, 색은 지금 `MARBLE_COLORS`, 사진 ON이면 사진. 이름은 구슬 바로 아래 색 글자 + 검은 외곽선(연결선 없음). 이름표 OFF면 숨김.
- 미니맵: 왼쪽 세로 스트립, 배율 4px/유닛, 폭 26유닛(104px), 높이는 goalY에 맞춤. 벽·장애물·구슬·뷰포트 사각형. 테두리 초록 1px.
- 순위 목록: 오른쪽 위, `n / total` 아래 구슬 색 이름 + `#순위`. 골인 ✓. 당첨 순위 줄은 금색 띠.
- 진행 바, 코스 이름, 타이머, 상태 글자는 캔버스 상단 얇은 줄 하나로 줄인다.
- 결과 카드(당첨자 큰 구슬 + 이름), 맵 추첨 결과 목록, 카운트다운은 지금 그대로 중앙 오버레이.

## 4. 설정 패널 (`src/App.tsx` DrawPage 핀볼 분기, `src/studio-refinement.css`)
- `.pinball-layout`을 단일 스테이지로 바꾸고, `draw-controls`를 스테이지 위 왼쪽 아래에 떠 있는 패널(`pinball-settings`)로 옮긴다. 폭 최대 560px, 반투명 배경.
- 패널 1행: 모드 · 코스 · 추첨 대상 · 당첨자 설정 · 추첨 시작/취소.
- 패널 2행: 수량 줄(선수별 구슬 수). 기본 접힘, `수량` 버튼으로 펼침. 직접 입력·맵 추첨은 기존 입력 칸이 이 자리에 들어간다.
- 추첨 시작 시 패널이 접히고 왼쪽 아래 `설정` 작은 버튼만 남는다. 완료 후에는 자동으로 다시 펼친다.
- 오른쪽 위 아이콘 줄: 1×/2×/4×, 이름표, 사진, 배치 섞기, 전체 화면. 전체 화면에서도 보인다.

## 검증
- `npm test`: 기존 5코스 × 1/3/10/15/25/60 × 시드 3개 완주·중복 없음 유지. 추가로 10개 기준 완주 틱 ≤ 6000(60초)을 모든 코스에서 확인.
- `npm run build` 통과.
- 개발 서버에서 Playwright로: 설정 패널이 한 화면에 들어가는지(1280×720, 1536×864, 1920×1080), 추첨 중 패널이 접히는지, 카메라가 선두를 따라가며 깔때기에서 줌인·슬로모션이 걸리는지(`render_game_to_text`의 camera/zoom/timeScale), 미니맵·순위 목록 표시, 콘솔 오류 0건.
